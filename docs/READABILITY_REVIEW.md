# Editor readability review

The editor agent reviews the native prepared frame used by canvas and exports. Codex, Pi and AGY share the same review tools.

For a normal request such as “Make the lettering readable, fix small text, overlaps and thick outlines”, the agent chooses the requested chapter/page range, audits it, inspects images, repairs selected layers and verifies the result. Start with a small range to review the visual result before asking for a whole project.

## Tools and native guarantees

- `set_edit_scope` with `readability: true` starts a review over the entire inclusive range. The range cannot shrink to hide unchecked pages. Typography/geometry edits also activate the review if an agent omitted the flag.
- `audit_readability` returns actual fitted text sizes at 390px and 960px page widths (never upscaling the page), overflow diagnostics, overlap/duplicate candidates, outline-to-font ratios and local background contrast. Follow pagination. The default 12px display font is a triage threshold, not a universal typography standard.
- Background contrast evaluates fill and outline together on each sample, including mixed artwork. When the fill alone loses contrast, `required_outline_px` reports source pixels for one visible outline pixel at the smallest reader width. Repair selects contrasting monochrome polarity from the local background, preserves working colored fills, and caps the halo relative to font size. Excessive-outline checks allow a necessary reader-visible halo. A halo too thin to survive scaling remains a `low_contrast` finding.
- Duplicate detection uses overlapping original OCR boxes even after automatic placement separates the rendered copies. It recognizes merged detections from source-word coverage, or complete generated translations reconstructed by disjoint OCR fragments when the merged source is garbled. Word occurrences, numbers and negations must survive. A separate heading can be redundant with a complete first source line in a larger detection. The audit lists the layers to preserve.
- Conflicting OCR clock digits are visual-review candidates with `automatic: false` and `requires_source_review: true`. Native removal requires a fresh original-artwork view. The agent compares both readings against the image and keeps uncertain cases as `needs_review`.
- `view_page` without crop/width returns phone and desktop images during a review. `element` crops around a layer while retaining surrounding artwork; `display_width` requests a simulated width. `original: true` shows unmodified source artwork before cleanup and translation, with an element crop anchored to its original OCR region. An original view never substitutes for verification of the translated page.
- `repair_text` takes `page` and optional `elements`. A page call checks its visible translated layers, up to 50 per call. It reconciles proven merged OCR while keeping the surviving dialogue complete. An unambiguous leading word missing from a generated fragment moves into that fragment before the merged layer is removed. A Vietnamese plural already explicit in the surviving sentence is retained. Other wording differences require visual review. Comparable dialogue in the same balloon receives a common fitted size. The search tries closer internal margins, line spacing and positions inside the contour. It preserves each balloon's geometry and font faces, adjusts outlines and contrast for the background, and saves one undo step.
- For remaining small text, `repair_text` also accepts `layout: {element, area: [x,y,width,height], avoid: [[x,y,width,height],...]}`. The agent inspects the art and marks permitted placement space and protected artwork in source-image pixels. Native tries bounded joint frame/font/fill/outline patches, protects other visible text, and returns up to three distinct candidates with full-page 390px/960px previews. Slanted text can retain its angle or use a level candidate; equally readable proposals prefer the original angle. Previewing saves nothing. `repair_text` with `page` and `candidate` applies the selected ID as one undo step; any project revision change invalidates it. The next search replaces prior candidates. Both the transformed frame (`frame_bounds`) and painted text (`bounds`) must remain inside the permitted area and outside protected regions; overflow, new overlaps and measured regressions are rejected. Wording, font faces, reading direction, source OCR and image layers remain unchanged.
- Free text on artwork additionally follows `source_placement`: its original OCR bounds with 10% padding per side for translated line breaks and outlines. Layout search intersects the permitted area with that limit and anchors proposals to the source. Direct style/geometry edits also reject increased departure from the source footprint; correcting a previously oversized edit may reduce its font. The phone-size threshold remains a warning, not a requirement to enlarge source-proportioned narration. Original artwork and visual review remain necessary because OCR boxes are approximate.
- Existing typography, geometry and line-break edits preview candidates before commit. They reject disappearing text, text moved beyond the page, new/worse overflow, unreadably smaller text, thicker excessive outlines, and worse measured contrast, including disappearing halos on mixed artwork. When a balloon is balanced, an oversized fragment can decrease to the common size while its smallest dialogue improves. A rejected visual candidate returns feedback for another attempt or an unresolved finding. Invalid tool arguments use the existing bounded recovery ledger. Omitted properties are preserved.
- After edits, view both sizes and use `verify_readability`. Each full-page view refreshes the current measurements. Repeated inspection and edits that leave the page unchanged retain its verification state. Each remaining issue needs a decision. Suspected collision/duplicate false positives can be kept. Measured problems must be repaired or marked `needs_review` with a reason. Native completion checks coverage and verifies that reviewed page state is still current.
- The progress panel shows checked pages and unresolved findings separately from saved edits. Finishing a review with unresolved findings does not mean those problems were repaired.

Readability repair preserves dialogue wording, artwork and cleanup. It cannot remove ordinary dialogue to pass an audit, hide cleanup, or rerun detection/OCR/translation/inpainting. Audited duplicate candidates can be removed after visual inspection. All native revision checks, retained project ownership and Undo remain in effect.

A proposal to delete or hide text without duplicate evidence returns `candidate_rejected` with no mutation. It does not create a pending malformed-call failure that could be cleared only by performing the prohibited edit. The agent must choose a safe layout repair or verify the remaining measured defect as `needs_review`. Invalid arguments, stale state and scope errors keep their bounded recovery checks. Production and the native installed-agent fixture execute the same layer review validation.

## Limits

Bounding rectangles do not prove glyph collisions. Background sampling is a triage measurement and requires visual checks of the filled glyphs; it does not certify accessibility. A dense printed page may still require zoom or a revised balloon layout on a phone. Ordinary batch fitting keeps existing geometry; layout search may resize a text frame only in explicitly permitted space. The agent owns visual identification of protected artwork: native rectangle constraints do not detect faces or panel borders. Review state and layout candidates belong to the current agent turn and are not a persistent project audit database.

## Validation

Focused native tests cover real fitted-font diagnostics, device scaling, hidden text, overlap/duplicate candidates, background-aware contrast, regression rejection, coverage, stale page verification and honest unresolved decisions. A detached real-project fixture checks five manga pages, rendered at both widths, and asserts unchanged words, bubble geometry, unrelated typography and artwork/cleanup pixels. It intentionally submits smaller text with a huge outline to confirm rejection before saving. Test images and project copies stay under ignored `temp/`.

The installed-agent integration fixture uses the same scene edits and readability module on a detached two-page range. It is opt-in and requires an available signed-in CLI/model; native tests or a changed-property count alone are not autonomous visual acceptance.

Pi's managed installer launcher and npm JavaScript entry points are resolved through Node with explicit arguments. Editor sessions load Koharu's explicit tool extension and use Pi's `--no-approve` option for project-local resources. The user's configured Pi provider/model identifies the model, for example `local-proxy/ag/gemini-3.8-flash-high`.
